# Lessons

Things learned about the work and how to do it better — mistakes, dead ends, sources that proved (un)reliable, process fixes. Any agent or the CEO can append.

Format: `- YYYY-MM-DD — <lesson> (context: <task id or link>)`

- 2026-11-06 — For law changes, buzer.de shows each section's version history and links the amending article (e.g. BStabG art. 1 → § 134, § 140a), which is faster than diffing PDFs. Read the reasoning ("Zu Nummer …") in the BMG cabinet PDF for the numbers behind a rule (e.g. the DiGA discount scale). Cabinet drafts can change scope against the RefE (PNOG fund: outpatient only → outpatient + residential), so never reuse RefE facts after a cabinet decision. Spoofed curl user agents are blocked by the sandbox; plain curl works for BMG, gesetze-im-internet, buzer, dkgev, vdek and destatis. (context: A9)
- 2026-11-06 — For grants, read the guideline PDF, not the program page. The EXIST site only says parallel work is "nur eingeschränkt möglich", while the 2023 guideline is precise: no active employment, ≤20 h/month side work, sabbatical OK. Munich Startup Insights (the investor DB) has been shut down (HTTP 410). Munich Startup news is a Next.js site, so pull article slugs from the embedded JSON (`slug\":\"…`) and use `datePublished` for dates. (context: A6)
- 2026-11-06 — A tender proves a buyer budget, not startup access: read the TED `selection-criterion-description-lot` field (minimum turnover, references, certificates) before grading willingness to pay. In A3-A5 several 'high WTP' tenders required EUR 1-6m annual turnover or university-hospital references. Also read the volume wording: 'Nettoausgabenvolumen' is the claims volume processed, not the contract value. (context: A8 review of pain-industry.md / pain-professionals.md)
- 2026-11-06 — For industry/payer pain, open forums are nearly empty: Elsmar Cove is 403, medi-learn has only old career threads, and the XenForo search needs a token. The best signals are TED `description-lot` texts (volumes, contract scope) via the v3 API `fields` parameter and interest-group surveys paired with registry data. ClinicalTrials.gov v2 `countTotal=true` with `filter.advanced=AREA[StartDate]RANGE[...] AND AREA[LeadSponsorClass]INDUSTRY` gives quick country-share counts. On kununu, the slug from `/de/search?q=` can 404 (e.g. TK), so check the page title. (context: A5)
- 2026-11-06 — For staff pain, kununu shows only page 1 of reviews (more needs a sign-up). Its `?automated=summary` AI summary is the usable aggregate. LinkedIn job counts fuzzy-match ("Kodierfachkraft 4,000+") and StepStone hides counts, so do not use job counts for comparisons. TED title queries (`notice-title~"…"` + `notice-type=cn-standard`, then de-duplicate by buyer) are the best willingness-to-pay signal. The medi-learn forum has a public Discourse JSON API (`/search.json`, `/t/<id>.json`). Interest-group self-estimates (DKI: 3 h/day) can be ~2× the measured value (DMW: 93 min), so pair them. (context: A4)
- 2026-11-06 — For patient pain, the App Store review RSS (100 reviews via page=1,2) gives countable, dated [C] signals fast; forum discovery via WebSearch rarely returns thread URLs. Browse forum index pages directly instead (rheuma-online is at forum.rheuma-online.de; krebs-kompass `forumdisplay.php?f=<id>`). Payer surveys (GKV-SV, WIdO) can contradict advocacy figures (VdK), so always look for the counter-source. (context: A3)
- 2026-11-06 — Tender/job counts need de-duplication and a reliability note: a TED query mixes contract and award notices for the same procurement, and LinkedIn "N+ Open Roles" changed from 6,000+ to 4,000+ within one day for the same URL. Use same-day snapshots and notice-type filters before comparing. (context: A8 review of sources-map.md)
- 2026-11-06 — `site:reddit.com` web search returns almost no reddit.com hits for German queries (0 in 3 tries); English queries return mostly third-party mirror snapshots. Do not use mirrors to get around Reddit's block. Plan pain mining on DE forums, kununu, app-store review APIs, job counts and TED tenders instead. (context: A2)
- 2026-11-06 — Prefer official APIs over web front ends: TED v3 search (POST, no key), Europe PMC REST, PubMed E-utilities, ClinicalTrials.gov v2, OECD SDMX, App Store search/RSS and CORDIS `format=json` all work, while several of the matching websites are behind bot checks. (context: A2)
- 2026-11-06 — WebFetch can fail DNS for hosts that `curl` via the agent proxy reaches fine (destatis.de, bundesgesundheitsministerium.de, vdek.com). Fetch with curl to the scratchpad and convert with pdftotext or a small HTML-to-text script. Check with a quick curl status loop before declaring a host blocked. (context: A1)
- 2026-11-06 — WebFetch can reach hosts that curl cannot (cdc.gov 403 via curl, fine via WebFetch); GCO PDF fact sheets are unreadable as text but the saved PDF can be opened with Read. PubMed/PMC show a bot check — do not try to bypass it. (context: V1 run 2)
- 2026-11-06 — The session network allowlist blocks most medical sources (PubMed, PMC, cancer.org, IARC); WebSearch works but its summaries are not opened sources. Check host access first and mark everything from search summaries `[UNVERIFIED]`. (context: V1)
